Halting live orders

Disable one execute task, or set DRY_RUN=true in .env to stop every execute task at once. The CLI re-reads .env per run, so the next fire is already dry.

Disable-ScheduledTask -TaskPath '\AI-Projects\Edge-Radar-MikesAILab\' `
  -TaskName '<task>'

Positions already open are held, not flattened: exiting a 5–20c-wide book pays exactly the illiquidity penalty Gate 3.6 exists to avoid.

How it works

One equation, guarded by 21 gates.

Pull Kalshi's ask. Pull an independent fair value from sportsbooks and data feeds. The difference is the claimed edge; the fee comes off before anything else is judged, then the order meets the gates.

fair_value − market_ask = edge · edge − fee(price) ≥ floor and every gate passes → bet

Pipeline

Seven stages. Scan, size, execute, settle.

One entry point, scripts/scan.py, runs the chain. The scheduled execute tasks call it with --execute, a budget and a max-bets cap; the preview you run by hand stops after the gates.

01FetchKalshi markets and order books, plus the Odds API and data feeds, through a short-TTL cache.
02CategorizeTicker → market type. ML · SP · TO · FU · PR each pick a model.
03CompareFair value against the ask, net of fee, with a confidence tier and a composite score.
04CapBracket dedup keeps the sibling that can clear the gates; per-event caps apply.
05Risk21 gates in order. Reject or trim. Preview prints the verdicts.
06ExecuteFractional Kelly size, shard funding, RSA-signed limit order. Dry run logs identically.
07SettleOutcomes, measured fees, Brier pair, drift and post-kickoff alarms. make settle
